# Data and provenance

## Interaction labels

`data/raw/VirusHostInter.csv` is the frozen 8,849-row input distributed with the
Virus-host interactions predictor (VHIP) study by Bastien and colleagues. It
contains three study labels:

| Study label | Rows | Positive | Negative |
|---|---:|---:|---:|
| NahantCollection | 5,208 | 318 | 4,890 |
| NCBI_HR | 2,588 | 2,119 | 469 |
| StaphStudy | 1,053 | 333 | 720 |
| Total | 8,849 | 2,770 | 6,079 |

The project did not independently recreate these three component datasets. The
manuscript must therefore cite VHIP as the direct source and separately cite the
underlying studies only when discussing their biology. The four columns
`k3dist`, `k6dist`, `GCdiff`, and `Homology` were supplied in this frozen table;
they are not regenerated by this repository.

## Frozen genome coverage

The sequence-covered model uses:

- `external/phist_run/phages`: 1,418 phage FASTAs, named by NCBI accession.
- `external/phist_run/hosts`: 323 host FASTAs, named by normalized host taxon.
- `external/phist_run/phage_map.json` and `host_map.json`: staging maps used by
  the PHIST comparison.

The FASTA directories are intentionally excluded from Git because of their
size. The interaction input is VHIP Supporting Table S2
(`https://doi.org/10.1371/journal.pcbi.1011649.s010`), and the public viral/host
accession list is Supporting Table S5
(`https://doi.org/10.1371/journal.pcbi.1011649.s013`). The compact maps are kept
in the repository, but the current scripts do not automatically recreate the
byte-identical frozen FASTA bundle. Refreshed NCBI downloads must be versioned
and checksummed as a new input release.

Exact normalized identifiers are used. NCBI accession version suffixes are
handled by a deterministic alias (`NC_000866.4` -> `nc 000866`); fuzzy substring
matching is prohibited. `experiments/01_build_dataset.py` records resolution in
portable, repository-relative JSON maps under `data/cache_v2`.

Coverage is 1,947/8,849 pairs (22.0%), comprising 1,488 positives and 459
negatives. All 1,947 are from NCBI_HR. Consequently:

- `experiments/02_baseline.py` is the only multi-study/cross-study analysis and
  uses the four VHIP-supplied pair features.
- Sequence, GNN, PHIST/RaFAH-style, cocktail, and temporal results cannot be
  described as multi-database validation.
- Extending sequence coverage for NahantCollection and StaphStudy is the main
  missing computational validation step.

## Generated and frozen artifacts

- `data/interim_v2/interactions.csv`: cleaned full input.
- `data/interim_v2/interactions_modelable.csv`: frozen genome-covered subset.
- `data/interim_v2/seq_pair_features.csv`: locally computed pair-feature cache
  retained as a compact verified artifact.
- `data/results_v2`: saved metrics, compact pooled predictions, and figures.
- `data/archive_results_v1`: deprecated development output; never cite it.

`experiments/00_validate_release.py` checks the expected counts, frozen FASTA
coverage, required result files, and SHA-256 manifest. Its strict default
requires the local genomes; `--allow-missing-genomes` supports code-only public
clones while still validating all included checksums and result artifacts.

## Optional fetching

`experiments/fetch_host_genomes.py` and `fetch_nahant_genomes.py` populate the
separate caches `data/fastas/hosts` and `data/phages`. They do not replace the
frozen analysis inputs automatically. Set a real NCBI contact email in
`configs/default.yaml` before using Entrez and record any new accessions and
download dates before treating a rerun as a new frozen dataset version.

## Other raw files are not independent validation sets

- `virushostdb_raw.tsv` and `phagesdb_records_cache.json` are host-association
  resources without a matched dense experimentally tested negative matrix.
- `saureus_experimental_interactions.csv` is a small derivative of rows already
  represented in the VHIP table and contains two malformed rows; it is not an
  independent external test.
- `saureus_phage_interactions.csv` is a positive host-association/split table
  from the older v1 workflow, not a phage-by-strain infection/non-infection
  matrix.

These files must not be counted as additional databases validating the frozen
24-feature model. A suitable independent validation set needs pair-level
positive and negative assays, compatible phage and host genome accessions, and a
predeclared evaluation protocol.

## Label and matrix limitations

Positive and negative labels reflect the source assays. Untested phage-host
pairs are unknown; the cocktail code stores them as unavailable cells and does
not treat them as observed negatives when scoring. The evaluated target set is
host taxa with at least one observed positive, not a prospective clinical or
strain-level host-range panel.
